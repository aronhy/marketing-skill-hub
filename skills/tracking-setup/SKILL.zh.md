# 追踪配置

> 中文阅读版。给 AI 执行的指令见同目录 `SKILL.md`。

## 目标

每个广告平台都收到准确的购买（或线索）事件，不重复计数，并有一个独立的数据来源用来核对平台数据。

## 追踪方案

| 平台 | 浏览器端 | 服务器端 | 重点检查 |
|---|---|---|---|
| Meta | 像素 | 转化 API | 浏览器和服务器事件用同一个 `event_id` 去重；事件匹配质量良好 |
| Google | Google 代码 | 增强型转化；如用 GA4 则导入转化 | 传递金额和币种；每个目标只设一个主要转化 |
| TikTok | TikTok 像素 | Events API | 用 `event_id` 去重；传递金额和币种 |
| 分析 | GA4 | — | 定义关键事件，关联广告平台 |

Shopify 等主流建站平台优先用各广告平台的官方集成或应用，服务器端事件和去重都能自动处理。

## 标准电商事件

浏览页面 → 查看商品 → 加购 → 发起结账 → 添加支付信息 → 购买（带金额、币种、商品 ID）。线索类：浏览 → 提交线索 / 注册 →（可能的话）回传合格线索。

## UTM 规范

- `utm_source`：平台（facebook、google、tiktok、newsletter）
- `utm_medium`：paid_social、cpc、email、influencer
- `utm_campaign`：广告系列名
- `utm_content`：广告或素材 ID

全部小写、用下划线。

## 校验

1. 下一笔真实测试订单（之后退款）或提交测试线索
2. 用各平台测试工具检查：Meta 事件管理工具、Google Tag Assistant、TikTok 像素助手
3. 确认金额币种正确、事件只触发一次
4. 对比同一周平台报告的购买数与实际订单数。平台通常因归因重叠而多报；如果反过来差很多，多半是追踪坏了

## 隐私

- 网站要有说明追踪行为的隐私政策
- 美国多个州有隐私法，要求为数据「出售」或「共享」提供退出选项；欧盟或英国流量需先取得同意
- 各州法律不同且在变化，具体要求请自行确认

## 输出格式

追踪方案表、事件及参数清单、UTM 规范、逐步校验清单、现存问题及修复办法。
